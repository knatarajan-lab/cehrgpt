# CEHR-GPT Privacy Analysis

This guide covers measuring the privacy risk of synthetic patient sequences generated by CEHR-GPT. It runs four independent analyses against the real training data, a held-out real set, and the synthetic data:

| Analysis | Module | Question | Compute |
|---|---|---|---|
| Membership inference | `member_inference` | Are synthetic patients closer to training patients than to held-out patients? | NumPy |
| Attribute inference | `attribute_inference` | Given a patient's common attributes, how well does the nearest synthetic patient reveal their sensitive attributes? | NumPy |
| Nearest neighbor adversarial accuracy | `nearest_neighbor_inference` | Is the synthetic data more similar to the training data than to held-out data? | NumPy |
| Re-identification risk | `reid_inference` | How likely is it that a synthetic record matches a real person and reveals new information about them? | Spark |

All modules live in [`src/cehrgpt/analysis/privacy`](./src/cehrgpt/analysis/privacy). The analyses don't depend on each other, so they can run in any order.

## Prerequisites

Ensure you have:

1. **Train and test patient sequences**: `patient_sequence/train` and `patient_sequence/test`. The [data generation script](./data_generation.md) only creates these two folders if `$OMOP_DIR/patient_splits` exists. Otherwise it writes a single `patient_sequence` folder, which these commands can't use.
2. **Synthetic sequences**: generated by Step 1 of the [Synthetic Data Generation Guide](./synthetic_data_generation.md).
3. **Tokenizer**: the tokenizer saved with the trained model.
4. **Spark Environment**: required for re-identification risk only (see [Spark Setup README](./spark_setup.md)).

### Input data

Each dataset is a folder of parquet files. The scripts read the first four `concept_ids` tokens as `year:<year>`, `age:<age>`, gender, and race, and treat numeric tokens as OMOP concepts. Sequences generated with `--meds_format` start with a shorter prompt and have not been checked against these scripts.

| Analysis | Train | Test | Synthetic | Tokenizer |
|---|---|---|---|---|
| Membership inference | `concept_ids` | `concept_ids` | `concept_ids` | Yes |
| Attribute inference | `concept_ids` | Not used | `concept_ids` | Yes |
| Nearest neighbor | `concept_ids` | `concept_ids` | `concept_ids` | Yes |
| Re-identification | `concept_ids`, `person_id`, `num_of_concepts` | `concept_ids`, `person_id`, `num_of_concepts` | `concept_ids` | No |

### Dataset size

The three NumPy analyses sample `--num_of_samples` patients from each dataset without replacement, and fail with `ValueError: Cannot take a larger sample than population` if any dataset is too small. The examples below use 10,000, so generate at least that many synthetic patients and check the size of your test set.

The re-identification analysis uses all of the data. It treats train + test as the population, so a small test set makes the population estimate small as well.

### Memory

Each sampled patient becomes a vector with one element per tokenizer entry, plus demographics. For `n` patients and `D` vector elements, expect:

- **Patient vectors**: `n × D × 8` bytes per dataset. With `n = 10,000` and `D = 18,000`, that's about 1.4 GB.
- **Distance matrices**: `n × n × 8` bytes each, or about 800 MB at `n = 10,000`.
- **`--batched` (attribute inference only)**: `batch_size × batch_size × D × 8` bytes per batch pair. The default `--batch_size 1000` needs about 144 GB at `D = 18,000`, so use a much smaller batch size or leave `--batched` off.

## Required Environment Variables

```bash
export CEHRGPT_HOME=$(git rev-parse --show-toplevel)
export CEHR_GPT_DATA_DIR="/path/to/training/data"
export CEHR_GPT_MODEL_DIR="/path/to/trained/model"
export SYNTHETIC_DATA_OUTPUT_DIR="/path/to/generated/synthetic/data"
export SYNTHETIC_SEQUENCES="$SYNTHETIC_DATA_OUTPUT_DIR/top_p10000/generated_sequences"
export PRIVACY_ANALYSIS_OUTPUT_DIR="$SYNTHETIC_DATA_OUTPUT_DIR/privacy"
```

The `top_p10000` folder name depends on your sampling settings. It is `top_p10000` for `TopPStrategy` with `--top_p 1.0`, and changes with the strategy, temperature, and repetition penalty.

Most of the scripts don't create their output folder and only write results at the very end, so create the folders first:

```bash
mkdir -p $PRIVACY_ANALYSIS_OUTPUT_DIR/{mia,aia,nnaa,reid}
```

## Step 1: Membership Inference

```bash
python -u -m cehrgpt.analysis.privacy.member_inference \
  --training_data_folder $CEHR_GPT_DATA_DIR/patient_sequence/train \
  --evaluation_data_folder $CEHR_GPT_DATA_DIR/patient_sequence/test \
  --synthetic_data_folder $SYNTHETIC_SEQUENCES \
  --tokenizer_path $CEHR_GPT_MODEL_DIR \
  --output_folder $PRIVACY_ANALYSIS_OUTPUT_DIR/mia \
  --n_iterations 10 --num_of_samples 10000
```

For each sampled synthetic patient, this finds the squared distance to the nearest training patient (label 1) and the nearest test patient (label 0). It then predicts "member" when the distance is below 5.

**Output**: `mia/membership_inference_<timestamp>.parquet`, with one row per iteration and the columns `Iteration`, `Accuracy`, `Precision`, `Recall`, and `F1`.

**Reading the results**: accuracy near 0.5 means that the distance doesn't separate training from test patients. Higher accuracy indicates leakage. Precision and F1 are 0 when no distance falls below the threshold, which is expected for long patient histories, so look at accuracy first.

## Step 2: Attribute Inference

```bash
python -u -m cehrgpt.analysis.privacy.attribute_inference \
  --training_data_folder $CEHR_GPT_DATA_DIR/patient_sequence/train \
  --synthetic_data_folder $SYNTHETIC_SEQUENCES \
  --tokenizer_path $CEHR_GPT_MODEL_DIR \
  --attribute_config $CEHRGPT_HOME/src/cehrgpt/analysis/privacy/attribute_inference_config.yml \
  --output_folder $PRIVACY_ANALYSIS_OUTPUT_DIR/aia \
  --n_iterations 10 --num_of_samples 10000
```

The config lists 253 common attributes and 8,720 sensitive attributes as OMOP concept IDs. Review it for your dataset. Each sampled training patient is matched on demographics and common attributes to their nearest synthetic patient and, as a baseline, their nearest other training patient. The analysis then scores how well that match's sensitive attributes predict the patient's own.

**Output**: `aia/attribute_inference/attribute_inference_<timestamp>.parquet`, with one file per iteration and one row per sampled patient. The script creates the `attribute_inference` subfolder itself. The columns are `Precision`, `Recall`, and `F1`, each for `Synthetic Train` and `Train Train`.

**Reading the results**: compare `F1 Synthetic Train` with `F1 Train Train`. If the synthetic score is at or below the baseline, the synthetic data reveals no more than another real patient would. Precision and F1 from files generated before the precision fix on this branch are wrong and can exceed 1, so rerun this step to compare them. Recall from those files is still valid.

## Step 3: Nearest Neighbor Adversarial Accuracy

```bash
python -u -m cehrgpt.analysis.privacy.nearest_neighbor_inference \
  --training_data_folder $CEHR_GPT_DATA_DIR/patient_sequence/train \
  --evaluation_data_folder $CEHR_GPT_DATA_DIR/patient_sequence/test \
  --synthetic_data_folder $SYNTHETIC_SEQUENCES \
  --concept_tokenizer_path $CEHR_GPT_MODEL_DIR \
  --metrics_folder $PRIVACY_ANALYSIS_OUTPUT_DIR/nnaa \
  --n_iterations 10 --num_of_samples 10000
```

This script uses different argument names from the others: `--concept_tokenizer_path` and `--metrics_folder`. `--metrics_folder` is marked as optional, but the script fails at the end of the run without it.

The script computes adversarial accuracy against the training set and against the test set. Adversarial accuracy is how often a patient's nearest neighbor comes from their own dataset, averaged over both directions.

**Output**: `nnaa/nearest_neighbor_inference_<timestamp>.parquet`, with a single row whose `NNAAE` column holds a list with one value per iteration. Each value is the test accuracy minus the training accuracy. The two accuracies themselves are not saved.

**Reading the results**: values near 0 are the goal. Positive values mean that the synthetic data is harder to tell apart from training data than from held-out data, which suggests the model is memorizing training patients.

## Step 4: Re-identification Risk

```bash
python -u -m cehrgpt.analysis.privacy.reid_inference \
  --training_data_folder $CEHR_GPT_DATA_DIR/patient_sequence/train \
  --evaluation_data_folder $CEHR_GPT_DATA_DIR/patient_sequence/test \
  --synthetic_data_folder $SYNTHETIC_SEQUENCES \
  --output_folder $PRIVACY_ANALYSIS_OUTPUT_DIR/reid
```

This step needs Spark, and `--output_folder` must be a local path. Increase `--num_salts` (default 40) if joins run out of memory or stall on skewed groups.

Real and synthetic patients are matched on age, gender, race, and a set of 7 common conditions. A match counts as new information when the patient has more than 17 sensitive concepts in common with the synthetic record. The script estimates risk in both directions, using a factor of λ = 0.23 to account for matching errors:

- `A_term`: population-to-sample risk
- `B_term`: sample-to-population risk

The analysis runs once for each of 255 combinations of quasi-identifiers, starting a new Spark session each time. Before running on a new dataset, review these constants at the top of `reid_inference.py`, which have no command-line arguments:

- `VOCAB_SIZE`: sets the 17-concept threshold, as `int(VOCAB_SIZE * 0.001)`
- `COMMON_ATTRIBUTES`: the 7 common conditions

**Output**: `reid/<config>.parquet`, with one file per combination and one row holding `A_term` and `B_term`. The 10 digits in `<config>` are:

| Position | Meaning |
|---|---|
| 1 | Age: `1` is exact age, `0` is 10-year bands |
| 2–3 | Gender and race: always `0`, and always used for matching |
| 4–10 | Common condition, in `COMMON_ATTRIBUTES` order: `1` is used for matching, `0` is ignored |

**Resuming**: combinations with an existing output file are skipped, so you can rerun the same command after an interruption. To start over, for example with new synthetic data, use an empty output folder.

**Reading the results**: the script doesn't produce a final score. The summary below reports the worst case, the largest `A_term` or `B_term` across all combinations. A threshold of 0.09 is often used in the re-identification literature, but it isn't enforced by the code, so choose one that suits your governance requirements.

## Step 5: Summarize the Results

```bash
python - <<'EOF'
import glob
import os

import numpy as np
import pandas as pd

root = os.environ["PRIVACY_ANALYSIS_OUTPUT_DIR"]


def read_all(pattern):
    return [pd.read_parquet(p) for p in sorted(glob.glob(os.path.join(root, pattern)))]


mia = pd.concat(read_all("mia/*.parquet"))
print(f"Membership accuracy: {mia.Accuracy.mean():.4f} (std {mia.Accuracy.std():.4f})")

aia = pd.DataFrame(
    [frame.mean() for frame in read_all("aia/attribute_inference/*.parquet")]
)
print(f"Attribute F1, synthetic: {aia['F1 Synthetic Train'].mean():.4f}")
print(f"Attribute F1, baseline:  {aia['F1 Train Train'].mean():.4f}")

nnaa = np.concatenate([frame.NNAAE.iloc[0] for frame in read_all("nnaa/*.parquet")])
print(f"NNAAE: {nnaa.mean():.4f} (std {nnaa.std():.4f})")

reid = pd.concat(read_all("reid/*.parquet"))
print(f"Re-identification combinations: {len(reid)} of 255")
print(f"Max re-identification risk: {reid[['A_term', 'B_term']].max().max():.4f}")
EOF
```

Check that the re-identification line reports all 255 combinations before using the risk value. This summary reads every file in each folder, so use a separate output folder for each synthetic dataset.

## Known Issues

The commands above work around these where possible, but they can affect how you read the results.

| Location | Issue | Effect |
|---|---|---|
| [`utils.py:117`](./src/cehrgpt/analysis/privacy/utils.py:117) | Age is scaled by each dataset's own maximum. | The same age can get different values in different datasets, adding a small error to distances. |
| [`member_inference.py:61`](./src/cehrgpt/analysis/privacy/member_inference.py:61) | The scripts seed Python's `random`, but `DataFrame.sample` doesn't use it (also in `attribute_inference.py` and `nearest_neighbor_inference.py`). | Sampling differs between runs, so results aren't reproducible. |
| [`member_inference.py:25`](./src/cehrgpt/analysis/privacy/member_inference.py:25) | The threshold of 5 is fixed and applies to squared distance. | One differing concept adds 1 and a gender or race mismatch adds 2, so few patients with long histories fall below it. |
| [`member_inference.py:84`](./src/cehrgpt/analysis/privacy/member_inference.py:84) | Distances are computed for each synthetic patient, not each real patient. | Membership inference attacks usually start from the attacker's real records, so these results may not be comparable with those studies. |
| [`reid_inference.py:244`](./src/cehrgpt/analysis/privacy/reid_inference.py:244) | Numeric gender and race tokens stay in the concept list. | Unless they occur in at least half of patients, they can count as sensitive matches, even though matched patients always share them. |
| [`attribute_inference.py:58`](./src/cehrgpt/analysis/privacy/attribute_inference.py:58) | The file error handler is invalid. | A wrong `--attribute_config` path gives `TypeError: catching classes that do not inherit from BaseException` instead of the actual error. |
| [`attribute_inference.py:180`](./src/cehrgpt/analysis/privacy/attribute_inference.py:180) | File names only have one-second resolution. | Iterations that finish within the same second overwrite each other. This is only likely on very small samples. |
